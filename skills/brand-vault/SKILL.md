# Brand vault

The vault is the single source of truth for a brand's values. Deliverables reference tokens, never values, so a change to the vault changes everything built from it. Tokens use the W3C Design Tokens format (`$value`, `$type`, `{group.name}` aliases).

`scripts/vault.py` does the mechanics. Run `python3 <this skill's base directory>/scripts/vault.py <command>`.

## Structure

`<job>/vault/`:

- `tokens.json`: the source. Only the Identity designer edits it.
- `assets/`: master files of marks and logos (SVG), and font licence notes.
- `build/`: generated by `vault.py build`. Never edit these files by hand.
  - `tokens.css`: CSS custom properties for pages, prototypes and HTML decks.
  - `tokens.flat.json`: resolved values for scripts and other tools.
  - `blender.json`: linear RGBA for Blender. See the Blender note below.
  - `swatches.html`: the brand tokens page, used for review and gate packs.

Groups in `tokens.json`:

| Group | Holds | Rule |
|---|---|---|
| `color` | Primitives: the only raw colour values | Name by palette role (ink, paper, signal), not by use |
| `text`, `surface`, `border`, `accent` | Semantic colours | Alias a primitive; never hold a raw value |
| `font`, `weight` | Families and weights | Record every family's licence in `assets/` |
| `type` | The type scale | State the ratio in the brand book |
| `space`, `radius` | Spacing and corners | Everything spaces from this scale |
| `motion` | Durations and easing | Reduced-motion variants live in the code, using the same tokens |
| `expressive` | The expressive layer: extended palette, texture, shape, gradient, depth | **Optional.** Built for the surfaces the brief's expression budget names, and kept off the ones it does not. An unset slot is a decision, not an omission, so the vault validates without it; a filled one is type-checked like any other |

`text.default` on `surface.default` must pass WCAG AA (4.5:1), or the vault does not validate. **The expressive layer never overrides a contrast rule**: expression does not buy a readability exemption, and a gradient carrying body text must pass at its worst point rather than its average.

## Commands

```
vault.py init <job>/vault --name "<Brand>"   # template with every value unset
vault.py validate <job>/vault                # structure, values, aliases, the required contrast pair
vault.py build <job>/vault                   # writes build/ (run after every change)
vault.py contrast <job>/vault                # every text and accent pair, with WCAG verdicts
vault.py lint --vault <job>/vault <files>    # literal colours that bypass the vault
```

A plugin hook runs the lint after every write to an HTML, CSS, SVG or script file inside a job, and reports literal colours back to the agent. In HTML and CSS, reference `var(--token)`. In standalone SVG files, literal fills are allowed only when they exactly match a vault colour.

The lint and the hook skip three places, because literal values there are correct rather than sloppy:

| Skipped | Why |
|---|---|
| `vault/` and any `tokens.css` | The vault is where the values live |
| `20-territories/` | Territory boards are made before the vault exists |
| `30-identity/exploration/` | Mark exploration is drawing, not a deliverable |

Everything else in a job references tokens. A lint that cries wolf in the pre-vault stages is a lint everyone learns to ignore.

**The texture rule.** The lint also reports texture — grain, noise, overprint, repeating and conic gradients, image backgrounds — declared on a rule whose selector says the block holds running text (`p`, `li`, `td`, `.body`, `.copy`, `.entry` and the like). Texture behind body text destroys the contrast the vault's other rules exist to protect. Texture on a hero, a cover or a campaign panel is the point of the expressive layer and is not flagged.

## The tokens page

After each build, publish `build/swatches.html` as an artifact for the gate pack. When the account offers a Design System artifact type, the approved vault is also recorded there at the system gate, so later work and other tools can use it.

## External brands

For commissions under someone else's identity (for example `--brand external:ntt-data-brand`), there is no job vault and the lint is off. Follow the named skill or guidelines. If a commission needs tokens, for example to build an HTML page, create a vault that mirrors the external values exactly, and note in `tokens.json`'s `$description` where they came from.

## Blender note

Brand hex values are sRGB. Blender expects linear values and applies its own view transform by default, which washes colours out. Use `build/blender.json` for material colours and set the scene's view transform to Standard. Otherwise renders drift off-brand.
